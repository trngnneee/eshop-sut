## Preconditions
- Server đang chạy
- Tài khoản `test@eshop.com` tồn tại, `login_attempts = 0`

## Steps to Reproduce
1. Gửi `POST /api/login` với email đúng nhưng mật khẩu sai lần đầu tiên
2. Kiểm tra DB: `SELECT login_attempts FROM users WHERE email = 'test@eshop.com'`
3. Gửi lại với mật khẩu sai lần thứ hai
4. Kiểm tra `locked_until` trong DB

## Expected Result
- Sau lần sai 1: `login_attempts = 1`, `locked_until = NULL`
- Sau lần sai 2: `login_attempts = 2`, `locked_until = NULL`
- Sau lần sai 3: `login_attempts = 3`, `locked_until = NOW + 180s` ← **khóa tại lần 3**

## Actual Result
- Sau lần sai 1: `login_attempts = 2` (cộng +2 thay vì +1)
- Sau lần sai 2: `login_attempts = 4 ≥ 3`, `locked_until = NOW + 180s` ← **khóa tại lần 2 — sai**

## Root Cause
`server.js` dòng 54:
```javascript
// BUG
const newAttempts = user.login_attempts + 2;

// FIX
const newAttempts = user.login_attempts + 1;
```

## Impact
- Tài khoản bị khóa sau **2 lần** sai thay vì **3 lần** theo đặc tả
- Gây khó chịu cho người dùng hợp lệ nhớ nhầm mật khẩu
- UX nghèo, khả năng khiếu nại cao
