## 2. Gap Explanations
1. **Tại sao khoảng trống xảy ra?**
   - AI ban đầu hoạt động ở mức kiểm thử hộp đen dựa trên tài liệu đặc tả (specification-based black-box testing) nên giả định SUT đã cài đặt đúng kiến trúc và phân quyền.
   - AI không tự động phát hiện được lỗi logic nhân đôi tiền hoặc hổng bảo mật phân quyền ở backend cho đến khi thực hiện phân tích tĩnh (static code audit) song song.
2. **Hành động khắc phục từ con người (Human Correction):**
   - Sinh viên đã kiểm tra trực tiếp mã nguồn React và Express để xác nhận phương thức lấy dữ liệu và chỉ ra các bug tĩnh.
   - Sinh viên định hướng thiết kế test case bổ sung cho lỗi phân quyền API (`TC-DASHBOARD-DT-004`) và test case biên kiểm thử doanh thu giá trị nhỏ (`TC-DASHBOARD-BVA-006`).

---

## 3. Lessons Learned & Recommendations
- **Bài học rút ra:** Luôn kết hợp phân tích mã nguồn (Static Code Analysis) với thiết kế kịch bản kiểm thử miền (Domain Testing) để có bộ test case có độ bao phủ bảo mật và logic tốt nhất.
- **Khuyến nghị sửa đổi code SUT:**
  - *Sửa BUG-FR13-C-01 ở `App.jsx`:* Bỏ nhân 2 (`o.total_amount * 2` thành `o.total_amount`).
  - *Sửa BUG-FR13-C-02 ở `server.js`:* Viết thêm middleware `requireAdmin` để kiểm tra `req.user.role === 'admin'` và áp dụng cho toàn bộ API Admin.
